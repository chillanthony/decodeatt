# R-KV 评估协议整理

本文整理自本地论文与笔记 `decodeatt/paper/r-kv.pdf` / `decodeatt/paper/r-kv.md`，并对照官方实现仓库 `Zefan-Cai/R-KV`。R-KV 是一个明确面向 **decoding-time long CoT generation** 的 KV cache compression 方法，因此比 DefensiveKV 更贴近我们当前的“边生成边压缩”实验场景。

## 1. 核心评估场景

R-KV 评估的不是长输入 prefill 后一次性压缩，而是 reasoning model 在自回归生成长 CoT 时，KV cache 随生成长度增长，系统周期性压缩已经生成的 KV cache。

官方 README 明确写法是 decoding-time compression：新生成 token 先进入 staging buffer，生成一个固定长度 segment 后，用 observation tokens 重新评分并把 cache 压回预算内。官方也特别提醒：HuggingFace 实现是 decoding-time compression，不应直接当作 prefill-stage long-prompt compressor 或 TTFT 优化方法使用。

因此整理 R-KV 评估协议时，必须标注为：

```text
场景：long reasoning generation / decoding-time KV cache compression
压缩对象：模型已经生成的 reasoning trace KV
触发方式：每生成固定长度 buffer/segment 后压缩一次
目标：在长 CoT 生成中降低 KV memory，同时保持数学推理正确率
```

## 2. 方法与 baseline

### 2.1 R-KV 方法口径

R-KV 的核心流程：

1. **Budget cache + buffer**  
   KV cache 被分成两部分：
   - `B_budget`：压缩后长期保留的预算 cache。
   - `B_buffer`：最近新生成 token 的 staging buffer。

2. **周期性触发压缩**  
   每生成 `B_buffer=128` 个 token 左右触发一次压缩。官方 HuggingFace runner 中对应：

   ```bash
   --divide_method step_length
   --divide_length 128
   ```

3. **observation tokens**  
   buffer 末尾 `α=8` 个 token 作为 observation tokens，用它们的 query 对候选 KV 计算重要性。

4. **importance scoring**  
   基于 observation tokens 对候选 KV 的 attention 分数。GQA 下对同一 KV head 对应的 query heads 做 group max，再重归一化。随后用局部 max-pooling 稳定分数。

5. **redundancy estimation**  
   对 key 向量做 cosine similarity，估计 token 冗余度。高相似、重复性强的 token 会被扣分。

6. **joint selection**  
   最终分数：

   ```text
   Z = λ * importance - (1 - λ) * redundancy
   ```

   默认 `λ=0.1`。保留 top scoring candidate tokens，并保留最后 `α` 个 observation tokens。

### 2.2 Baseline

论文主评测 baseline：

- `FullKV`：不压缩，作为质量上界。
- `SnapKV`：从 prompt-time KV compression 适配到 decoding-time；用相同 buffer/压缩间隔和相同预算。

论文重点不是堆很多 long-context baseline，而是证明：在 reasoning traces 中，纯 attention-based selection 会被重复 self-reflection 污染；因此 SnapKV 作为 attention-only baseline 是关键对照。

官方 README 也说明：PyramidKV、HeadKV 等 head/layer budget schedule 与 R-KV 正交，因此主实验未作为核心 baseline。

## 3. 模型设置

论文主实验使用两个 DeepSeek-R1 distilled reasoning models：

| 简称 | HuggingFace checkpoint |
|---|---|
| R1-Llama-8B | `deepseek-ai/DeepSeek-R1-Distill-Llama-8B` |
| R1-Qwen-14B | `deepseek-ai/DeepSeek-R1-Distill-Qwen-14B` |

官方 README 示例命令使用 R1-Llama-8B：

```bash
--model_path deepseek-ai/DeepSeek-R1-Distill-Llama-8B
```

注意：DeepSeek-R1-Distill 这类 chat/reasoning 模型通常需要 `--use_chat_template`，否则不一定进入训练时的 `<think>` reasoning 格式。官方 README 明确建议评估 DeepSeek-R1-distill 或其他 chat 模型时加上：

```bash
--use_chat_template
```

## 4. 数据集设置

论文主实验集中在数学推理：

| 数据集 | 平均生成长度 / solution | 最大生成长度 |
|---|---:|---:|
| MATH-500 | 约 2,979 tokens | 16,384 |
| AIME 2024 | 约 15,536 tokens | 32,768 |

本地笔记中也提到部分实验包含 AIME 2025，但论文主结果主要是 MATH-500 与 AIME 2024。

官方 HuggingFace 命令示例使用：

```bash
--dataset_path ./data/aime24.jsonl
```

建议我们的复现协议：

- MATH-500：`max_new_tokens / max_length = 16384`
- AIME 2024：`max_new_tokens / max_length = 32768`
- 如果资源有限，先跑 AIME24 小样本或 MATH-500 子集；但正式对齐论文要用完整数据集。

## 5. 采样与 pass@1 口径

论文使用 sampling，而不是 greedy：

```text
temperature = 0.6
top_p = 0.95
num_return_sequences = 64
```

报告指标是 pass@1。这里的 pass@1 不是只采样一次，而是每题采样 64 条 candidate，再按评测脚本统计 pass@1 / accuracy 分布。这一点比单次采样更稳健，也显著增加计算成本。

官方 README 示例：

```bash
--do_sample
--temperature 0.6
--top_p 0.95
```

并补充说明：paper-style candidate generation 还需要：

```bash
--num_return_sequences 64
```

我们的协议中应区分两种模式：

| 模式 | 用途 | 设置 |
|---|---|---|
| smoke / debug | 快速检查实现是否正常 | `num_return_sequences=1`，可 greedy 或 sampling |
| paper-style | 对齐论文精度 | `num_return_sequences=64`, `temperature=0.6`, `top_p=0.95` |

## 6. KV budget / cache ratio 口径

R-KV 同时报告 ratio-based budget 和 fixed-token budget。

### 6.1 固定 token 预算

官方 HuggingFace runner 用：

```bash
--kv_budget 1024
```

含义是压缩后长期保留的 KV budget，即 `B_budget`。observation window / buffer 另有参数控制。

论文 lossless fixed-token budget 摘要：

| 模型 | 数据集 | lossless fixed budget |
|---|---|---:|
| R1-Llama-8B | MATH-500 | 1024 |
| R1-Llama-8B | AIME 2024 | 1536 |
| R1-Qwen-14B | MATH-500 | 1536 |
| R1-Qwen-14B | AIME 2024 | 3072 |

### 6.2 ratio-based budget

论文也报告保留比例：

| 模型 | 数据集 | lossless cache ratio |
|---|---|---:|
| R1-Llama-8B | MATH-500 | 34% |
| R1-Llama-8B | AIME 2024 | 10% |
| R1-Qwen-14B | MATH-500 | 54% |
| R1-Qwen-14B | AIME 2024 | 25% |

解读时要小心：AIME 输出更长，因此 10% ratio 对应的绝对 token 数并不小。论文也同时给 fixed-token budget，建议我们的报告同时给：

```text
cache_ratio
kv_budget_abs
final_cache_len
mean_effective_cache_len
```

避免只说“10% cache 无损”造成误解。

## 7. 默认超参数

论文与官方 README 的默认超参数：

| 参数 | 含义 | 默认值 |
|---|---|---:|
| `B_buffer` / `divide_length` | staging buffer / 压缩触发间隔 | 128 |
| `α` / `window_size` | observation tokens 数量 | 8 |
| `λ` / `mix_lambda` | importance 与 redundancy 权重 | 0.1 |
| `max_length` MATH | 最大生成长度 | 16,384 |
| `max_length` AIME | 最大生成长度 | 32,768 |
| `temperature` | sampling temperature | 0.6 |
| `top_p` | nucleus sampling | 0.95 |
| `num_return_sequences` | 每题采样数 | 64 |

官方示例命令：

```bash
python3 ./run_math.py \
  --dataset_path ./data/aime24.jsonl \
  --save_path ./outputs/output.jsonl \
  --model_path deepseek-ai/DeepSeek-R1-Distill-Llama-8B \
  --max_length 32768 \
  --eval_batch_size 1 \
  --method rkv \
  --kv_budget 1024 \
  --window_size 8 \
  --mix_lambda 0.1 \
  --divide_method step_length \
  --divide_length 128 \
  --do_sample \
  --temperature 0.6 \
  --top_p 0.95
```

paper-style 还应加：

```bash
--num_return_sequences 64
--use_chat_template
```

## 9. 指标计算

### 9.1 精度指标

主指标：

```text
pass@1 / accuracy
```

数学答案需要经过 latex / symbolic normalization。官方 HuggingFace evaluation 需要额外安装：

```bash
cd HuggingFace/evaluation/latex2sympy
pip install -e .
cd ..
pip install -r requirements.txt
```

我们的协议中应记录：

- `raw_output`
- `extracted_answer`
- `gold_answer`
- `ok`
- `gen_len`
- 每题 64 次 sampling 的 candidate-level correctness
- per-problem pass@1 / aggregate accuracy

### 9.2 KV 压缩指标

建议记录：

- `kv_budget`
- `buffer_size / divide_length`
- `window_size`
- `mix_lambda`
- `final_cache_len`
- `mean_compression_ratio`
- `total_evicted_tokens`
- `mean_evicted_per_event`
- `cache_len_curve`
- 每次 eviction 的 `cache_len_before/after`

这些和我们当前 runner 新加的 log 字段可以直接对齐。

### 9.3 效率指标

论文报告：

- memory saving
- 最大 batch size
- throughput / tokens per second
- generated tokens
- decoding time

官方 README 给出的代表结果：

| 输出长度 | 设置 | 预算 | memory saving | batch gain | TPS gain |
|---:|---|---:|---:|---:|---:|
| 8K | ratio | 10% | 90% | 7.7x | 4.5x |
| 16K | ratio | 10% | 90% | 9.0x | 6.6x |
| 8K | fixed | 1024 | 87.5% | 6.5x | 3.8x |
| 16K | fixed | 1024 | 93.75% | 13.4x | 9.2x |

我们的 log 应记录：

- `elapsed_sec`
- `tokens_per_sec`
- `peak_memory_bytes`
- `prefill_sec`
- `decode_sec`
- `decode_forward_sec`
- `attention_observation_sec`
- `eviction_sec_total`
- `eviction_sec_mean`

## 10. 消融实验

论文重点消融：

1. `λ` sweep：验证 importance 和 redundancy 的互补性。
   - `λ=1`：退化为 pure attention / SnapKV-like。
   - `λ=0`：只看 redundancy。
   - `λ=0.1`：正文推荐，表现最好或最稳。

2. budget sweep：
   - fixed budget：1024 / 1536 / 3072 等。
   - ratio budget：10% / 16% / 25% / 34% / 54% 等。

3. R-KV vs SnapKV token selection visualization：
   - SnapKV 保留 token 往往集中在 query 附近，且包含重复 self-reflection。
   - R-KV 保留 token 分布更广、更少冗余。

我们的复现建议至少包括：

```text
FullKV
SnapKV@same_budget
RKV@same_budget
RKV λ sweep: 0, 0.1, 0.5, 1.0
RKV budget sweep: 512, 1024, 1536, 2048, 3072
```

## 12. 与 decodeatt 当前框架对齐

我们当前框架已有：

- `fullkv`
- `snapkv`
- `rkv`
- `h2o`
- `streamingllm`
- `window`
- `random`

其中最接近论文协议的是：

```text
fullkv vs snapkv@B vs rkv@B
```

关键对齐点：

| 论文 / 官方 R-KV | decodeatt 当前字段 |
|---|---|
| `kv_budget` | arm 中的 `rkv@B` |
| `B_buffer=128` | `evict_every=128` |
| `α=8` | `policy_params.rkv.alpha=8` |
| `λ=0.1` | `policy_params.rkv.lambda=0.1` |
| `kernel_size` / pooling | `policy_params.rkv.pool_kernel=7` 当前实现；若严格对齐需确认官方 kernel |
| AIME max length 32768 | `--max-new 32768` |
| MATH max length 16384 | `--max-new 16384` |
| sampling | `temperature=0.6`, `top_p=0.95` |

需要注意：

1. 官方 R-KV paper-style 是每题 64 次 sampling；我们默认 eval 不是 64 samples。
2. 官方有自己的 answer extraction / latex2sympy；我们用 `math_verify`，需要检查一致性。
3. 官方 SnapKV 是按相同 decoding interval 适配；我们当前 SnapKV cache-aware selection 也按 eviction interval 触发，但要确认 observation logits 的计算和 pooling 与官方一致。
4. 官方效率实验重点是 batch scaling；我们当前 evaluator 主要是 batch=1 单题循环，不能直接复现吞吐提升曲线。

## 14. 主要结论口径

论文主张：

- R-KV 在 reasoning models 的长 CoT 生成中，能用很小 KV cache 保持接近 FullKV 的数学推理精度。
- R1-Llama-8B 在 AIME24 上约 10% cache ratio 可无损；16% cache ratio 甚至约 105% FullKV。
- R1-Llama-8B 在 MATH-500 上约 34% cache ratio 无损；fixed budget 1024 无损。
- 相比 SnapKV，最高可提升约 40% accuracy。
- 效率收益主要来自固定 cache 使 batch size 大幅增加，而不只是 batch=1 latency。

复现实验报告时，不建议只写“10% cache 无损”，应同时报告 fixed budget、平均生成长度和最终有效 cache 长度。
