# 文档规范

- 项目文档统一使用中文，内容保持简要，只保留必要结论和依据。

# 项目记忆维护

- `note/AGENTS.md`：保存永久规则、环境限制和工作方式。
- `note/STATUS.md`：分为当前阶段（状态、阻塞和关键指标等信息）、最近完成几步、之后几步的规划、已完成归档，四个部分都用 # 标题，前三个部分合计超过50行的时候要压缩已有记录，把多余的的步骤记录移动到“已完成归档”部分，新的条目放到相应部分的末尾而不是开头，语言尽量保持简要。
- `note/MEMORY.md`：只追加已验证结论、实验结果、踩坑和否决方案的摘要。
- 以上三个项目记忆文件仅在本地维护，不纳入 Git 跟踪。
- 每次工作前读取以上三个文件；完成后更新 `STATUS.md`，有新的长期结论时再更新 `MEMORY.md`。
- 用户日常只需查看 `STATUS.md`。

# 工作流程

- 评测主入口是 `scripts/eval.py`；正式实验使用 `configs/experiments/`，单策略补跑或调试使用 `configs/onestrategy/`。
- 修改评测流程或策略后，从仓库根目录运行 `PYTHON_BIN -m pytest tests/test_*.py`；需要导入仓库代码时确保已设置 `PYTHONPATH`。
- 结果输出默认控制在几 KB，优先使用 `log_mode=brief`；只有明确需要逐题文本、候选、cache 曲线或淘汰事件时才使用完整日志。

# 环境限制

- 使用 conda 提供的 Python 3.11 环境，脚本通过 `PYTHON_BIN` 指定解释器。
- 从仓库外运行脚本时必须设置 `PYTHONPATH` 指向仓库根目录。
- 多卡运行前按机器设置 `HF_HOME`、`HF_ENDPOINT` 和 `HF_DATASETS_CACHE`，不要依赖另一台机器的默认路径。
