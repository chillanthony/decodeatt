## 当前锁定的正确性契约

以下断言在升级后**必须继续成立**。每条都是升级的验证点。

### 1. R-KV 选择语义对齐上游（`test_rkv_parity.py`，5 项）

| 测试 | 契约 |
|---|---|
| `test_importance_matches_reference_candidate_softmax` | `rkv_importance` == 参考实现（candidate softmax + max_pool1d），`rtol=1e-5, atol=1e-6` |
| `test_redundancy_matches_reference_cal_similarity` | `rkv_redundancy` == 上游 `cal_similarity`，同容差 |
| `test_select_rkv_matches_reference_single_layer_single_head` | `select_rkv_global` 选出的索引集合 == 参考实现（排序后逐元素相等） |
| `test_select_rkv_debug_scores_are_aligned` | debug 分数：前 `n_cand` 项有限，尾部为 `inf`；`backend_keep == idx` |
| `test_select_rkv_rejects_budget_not_greater_than_alpha` | `budget <= alpha` 抛出 `ValueError("budget must be greater than alpha")` |

**固定输入**：`torch.manual_seed(7)`，`n_total=14`，`window=4`，`total_budget=9`，`head_dim=6`。
**固定超参**：`lambda=0.1`，`pool_kernel=7`，`similarity_threshold=0.5`，`retain_ratio=0.1`，`retain_direction="last"`，`redundancy_chunk=3`。

### 2. 各 baseline 策略对齐官方实现（`test_official_baseline_parity.py`，7 项）

| 测试 | 契约 |
|---|---|
| `test_snapkv_matches_official_update_indices` | SnapKV maxpool 变体选出索引 == 官方 |
| `test_snapkv_avgpool_matches_official_pooling_variant` | SnapKV avgpool 变体选出索引 == 官方 |
| `test_h2o_matches_official_shared_head_indices` | H2O 跨头共享选择 == 官方 |
| `test_streamingllm_matches_official_first_plus_local_window` | StreamingLLM：`budget=7, sink=3, n=12` → **精确索引 `[0,1,2,8,9,10,11]`**（精确相等，无容差） |
| `test_rkv_layer_selector_matches_official_update_indices` | 分层 `select_rkv` == 官方 update_indices |
| `test_headwise_cache_compaction_gathers_each_head_independently` | `_compact_cache` 按头独立 gather；验证 `keys[0,:,:,0] == [[3,1,4],[5,7,9]]`，`values == [[103,101,104],[105,107,109]]` |
| `test_runner_attention_logit_rows_match_official_scores_without_attentions` | `_attention_logit_rows` 在不依赖 `output_attentions` 的情况下复现官方 score |

**固定输入**：`torch.manual_seed(11)`，`n_total=13`，`head_dim=5`，`kv_heads=2`。

> 这两组是**升级风险最集中的地方**——它们直接验证 `_compact_cache` 对 `cache.layers[i].keys/values`
> 的读写语义。升级 `transformers` 后如果 `DynamicCache` 结构变了，**这里会第一个红**。

### 3. 真实 transformers 前向数值锚点（`test_tideprobe_traces.py`）

`test_layer_mask_probe_with_tiny_llama` 会**实际构造一个 `LlamaForCausalLM`**（随机权重）
并跑前向，是唯一真正依赖 `transformers` 数值行为的测试。

**模型配置**：`vocab_size=32, hidden_size=16, intermediate_size=32, num_hidden_layers=2,
num_attention_heads=4, num_key_value_heads=2, max_position_embeddings=64`，
`_attn_implementation="sdpa"`，`torch.manual_seed(3)`。

**断言**：6 行结果、`max(baseline_max_abs_error) < 1e-4`、`nll_sparse` 全有限、至少一个 `|nll_delta| > 1e-7`。

**本次实测值**（升级后应保持不变；若只差在末位浮点，可接受）：

```

              window 3.466345 / 3.470705
                 rkv 3.459466 / 3.470115
nll_delta:   random +5.069e-03 / +8.561e-03
              window +3.445e-03 / +7.806e-03
                 rkv -3.433e-03 / +7.215e-03
```

**`fullkv_nll`（8 个生成位的 NLL，作为数值指纹）**：

```
[3.455906, 3.313243, 3.353125, 3.358193, 3.508919, 3.521588, 3.522815, 3.491856]
```

> **这是升级时最有价值的一行数字**。同一个随机种子 + 同一份权重初始化，只要
> 模型前向数值一致，这 8 个数就应该逐位重现。它是判断"升级后 transformers
> 前向是否发生了实质变化"的最快信号——比跑一次完整评测快得多。

### 4. 批处理与缓存压缩契约（`test_batch_generation.py`，7 项）

覆盖 `_compact_cache_update_batch`、`generate_token_evict_batch`、`pad_input_ids`、
跨题评测的顺序还原。其中 `test_batched_rkv_selection_matches_independent_requests`
与 `test_masked_batched_rkv_matches_unpadded_requests` 验证"批处理结果 == 单请求结果"，
是引入 padding 后正确性的核心保证。

**运行时打印**（非断言，仅供观察性能）：

```
[1/3] short  cross_batch=2 candidates=3 tok/s=89803.09
[2/3] long   cross_batch=1 candidates=3 tok/s=54544.81
[3/3] medium cross_batch=2 candidates=3 tok/s=89803.09
```

### 5. 评测协议与日志格式（`test_brief_log_mode.py` + `test_strategy_baselines.py`）

- `brief_payload` 不携带大体积生成详情，`full_payload` 保持向后兼容。
- **`brief` 与 `full` 两种模式必须产出相同的 summary** ——这是防止日志压缩悄悄改变结果的关键约束。
- shard summary 的合并按 candidate 加权。
- legacy tuple cache 仍可被 summarize 和 compact（`test_legacy_tuple_cache_can_be_summarized_and_compacted`）。
  **注意**：这条正是最可能被升级打破的向后兼容路径，因为新 `transformers` 已不返回 tuple cache。
  实测：**升级后仍通过**。该用例是显式手工构造 tuple cache 送进来的（不依赖 forward 的返回值），
  因此在 5.17 上不受影响；真正的风险只在"新版本 forward 不再产出 tuple"，
  而本项目本来就不依赖它。

| `kv_eviction/runner_token.py:1394` | 同传 `cache_position` + `attention_mask` + `position_ids`，跨版本 forward 签名敏感 | **未触发**——数值逐位一致，说明前向等价 |

### 升级后新增的注意点

1. **`crop` 弃用警告**：transformers 5.17 在走 cache 裁剪时会打印
   `Calling 'crop' with a positive value is deprecated and will be removed in version 5.18`。
   目前只是警告，但 5.18 会移除该用法——**下次升 transformers 时必须处理**。
2. **`test_tideprobe_traces.py` 无 `__main__` 入口**，需按函数名逐个调用；
   上表的 49 个用例数是把它按 13 个函数计入手工统计的。
3. **`transforms 5.x` 的破坏性并未体现在本项目路径上**，因为本项目的 eviction 走的是
   自实现的 `_CacheLayerView` 适配层，而非 HF 的 monkeypatch 路径。这层适配是本仓库
   最有升级价值的部分，**保持它**。
